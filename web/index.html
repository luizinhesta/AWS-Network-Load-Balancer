AWS Luanti ALB/NLB

Arquitetura AWS com Application Load Balancer e Network Load Balancer para estudo e portfólio

Sobre o Projeto

Este projeto demonstra uma arquitetura completa na AWS utilizando Application Load Balancer (ALB) e Network Load Balancer (NLB) para balanceamento de carga em diferentes camadas de rede. O objetivo é ilustrar as diferenças entre Layer 7 (HTTP/HTTPS) e Layer 4 (TCP/UDP), utilizando EC2 Spot Instances, Auto Scaling Groups, Target Groups e boas práticas de segurança e monitoramento.

A infraestrutura hospeda um portal web informativo (este site) acessado via ALB com HTTPS, e um servidor de jogo Luanti acessado via NLB na porta UDP 30000. Toda a infraestrutura é criada manualmente via Console AWS, com documentação passo a passo detalhada para cada recurso.

Conectar ao Servidor de Jogo

Para jogar no servidor Luanti hospedado nesta infraestrutura, utilize o endereço abaixo:

game.seudominio.com:30000 Copiado!

Instruções de Conexão

  1. Baixe e instale o Luanti (anteriormente Minetest).
  2. Abra o Luanti e clique em Multiplayer.
  3. No campo Endereço, insira: game.seudominio.com
  4. No campo Porta, insira: 30000
  5. Escolha um nome de usuário e clique em Conectar.

Conceitos da Arquitetura

Application Load Balancer (ALB)

O Application Load Balancer opera na Layer 7 (camada de aplicação) do modelo OSI, tomando decisões de roteamento com base no conteúdo das requisições HTTP/HTTPS. Ele suporta terminação TLS, roteamento baseado em path e host, e integração nativa com o AWS Certificate Manager (ACM). Neste projeto, o ALB recebe o tráfego web na porta 443 (HTTPS), realiza a terminação TLS e encaminha as requisições para as instâncias Nginx na porta 80 via Target Group.

Network Load Balancer (NLB)

O Network Load Balancer opera na Layer 4 (camada de transporte), lidando com conexões TCP e UDP sem inspecionar o conteúdo dos pacotes. Ele oferece latência ultra-baixa e preserva o IP de origem do cliente. Neste projeto, o NLB recebe o tráfego UDP na porta 30000 e o encaminha diretamente para a instância EC2 que executa o servidor Luanti via Docker, sem modificar os pacotes do protocolo do jogo.

Spot Instances

EC2 Spot Instances são instâncias que utilizam capacidade ociosa da AWS com descontos de até 90% em relação ao preço On-Demand. Em contrapartida, a AWS pode interromper essas instâncias com um aviso de 2 minutos quando precisa recuperar a capacidade. Neste projeto, utilizamos múltiplos tipos de instância (t3.small, t3a.small, t2.small) para diversificação de capacidade e reduzir a probabilidade de interrupção simultânea, combinado com Auto Scaling para reposição automática.

Auto Scaling

Auto Scaling Groups (ASG) permitem ajustar automaticamente o número de instâncias EC2 com base em demanda ou métricas. O ASG do portal web utiliza uma política de Target Tracking que mantém a utilização média de CPU em 70%, escalando de 1 a 2 instâncias conforme necessário. O ASG do servidor de jogo opera com capacidade fixa (min=1, max=1) para self-healing: se a instância falhar ou for interrompida pelo Spot, o ASG automaticamente provisiona uma nova instância em até 300 segundos.
